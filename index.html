Exploration cycle

Start with a question.
Follow what it connects to.

The project investigates a recursive workflow for navigating meteorological knowledge. Each discovered concept can guide the next retrieval step, while sources and relationships remain visible for review.

01 · SEED

Frame a meteorological question

Begin from a phenomenon, observation, forecast, place, time period, or domain concept.

02 · DISCOVER

Retrieve related knowledge

Identify relevant entities, terms, and links from the knowledge sources selected for the task.

03 · EXPAND

Explore recursively

Use promising discoveries to guide another focused step, with scope and stopping conditions kept explicit.

04 · CONNECT

Construct an inspectable graph

Represent explored concepts as nodes and their evidence-backed relationships as edges.

Development · Methodology

How the knowledge graph is built

A focused pipeline turns meteorological research into source-linked relationships, then follows selected discoveries to build a three-level graph.

01 · PREPARE

Build a literature corpus

Extract paper text and available metadata from PDFs, divide the text into paragraphs, and retain each passage’s source details for later tracing.

02 · RETRIEVE

Find relevant evidence

Use semantic search to find paragraphs related to each meteorological topic. Rank and filter the passages, then provide the strongest matches as context for relationship extraction.

03 · GENERATE

Extract relationships

A language model proposes a directed subject–relation–object claim from each selected passage, using a defined set of meteorological relation types. The passage stays attached as paragraph-level evidence.

04 · EXPAND

Explore recursively

The starting topic forms Level 1. Selected relationship targets become topics for Levels 2 and 3, expanding the graph while limiting how many passages and child topics are considered at each step.

05 · EVALUATE

Review generated claims

After generation is complete, three independent language-model judges assess source support and claim generality. Their scores are averaged to summarize each candidate’s evaluation.

Experiment settings: three topic levels; passage widths of 2, 3, or 5; and expansion breadths of 2, 3, or 5. Width limits the passages considered per topic; breadth limits the child topics expanded. Judge scores support review and should be validated against meteorology expert assessments.

Knowledge graph construction · Underlying model

Build a knowledge graph from topics, claims, and evidence.

KG construction begins with meteorological topics and their associated triplets, then turns each stated relationship into an explicit assertion with a subject, predicate, and object. Assertions are linked to topic resources and to evidence records that capture a source link and title. This separates domain concepts, claims, and provenance, making it possible to inspect how a relationship was represented and where it came from. As assertions accumulate, their shared subjects, objects, and topics form a connected graph that can be queried and explored to reveal relationships across meteorological domains.

Topic resource

Topic

A named meteorological concept or area of interest that provides a recognizable entry point into the graph. Topics can group related assertions and support recursive exploration into connected concepts.

  • hasNameText
hasAssertion→
Knowledge statement

Assertion

A single statement about meteorological knowledge, represented as a subject–predicate–object triplet. The subject identifies what the statement is about, the predicate names the relationship, and the object gives the related concept or value.

Provenance resource

Evidence

Provenance for an assertion: a titled source and link that help readers check, interpret, and trace the supporting information.

The UN Meteorology workbook supplies the topic triplets used to seed and organize this domain knowledge. Each triplet can be represented as an assertion, associated with its topic, and connected to a source evidence record. This gives the graph a consistent path from meteorological concepts, through explicit relationships, to the material supporting those relationships.

Competency questions · Query patterns

Ask cause-and-effect questions about climate knowledge.

These twelve parameterized SPARQL templates query topic, assertion, and evidence records in the Agentic Meteorological Knowledge Graph. The assertion predicates are stored as text literals, so the queries compare their literal values.

Running the examples: Provide a search phrase as the bound value for ?term and run the query against combined_meteorology.ttl.gz. The graph file is not included in this website repository. The query patterns below document the supplied workflow and do not display live query results.
CQ1 · What factors are linked to this climate effect?

Input: Effect or object phrase. Bind the input as the SPARQL variable ?term.

PREFIX : <http://meteo_onto.org/meteo_knowledge/>

SELECT ?subject ?predicate ?object ?claim WHERE {
  ?assertion :hasSubject ?subject ;
             :hasPredicate ?predicate ;
             :hasObject ?object ;
             :hasClaim ?claim .
  VALUES ?predicate { "causes" "contributes_positively_to" "contributes_negatively_to" "affects_positively" "affects_negatively" "mitigates" }
  FILTER(CONTAINS(LCASE(STR(?object)), LCASE(STR(?term))))
}

CQ9 · What evidence and sources support cause-and-effect claims for this topic?

Input: Topic name or phrase. Bind the input as the SPARQL variable ?term.

PREFIX : <http://meteo_onto.org/meteo_knowledge/>

SELECT ?claim ?subject ?predicate ?object ?source ?text WHERE {
  ?topic :hasName ?topicName ;
         :hasAssertion ?assertion .
  ?assertion :hasSubject ?subject ;
             :hasPredicate ?predicate ;
             :hasObject ?object ;
             :hasClaim ?claim ;
             :hasEvidence ?evidence .
  VALUES ?predicate { "causes" "contributes_positively_to" "contributes_negatively_to" "affects_positively" "affects_negatively" "mitigates" }
  OPTIONAL { ?evidence :hasSource ?source }
  OPTIONAL { ?evidence :hasText ?text }
  FILTER(CONTAINS(LCASE(STR(?topicName)), LCASE(STR(?term))))
}
